# Entity Mappings

Mapping files resolve provider-specific identifiers and names to canonical
internal IDs. They are required before source records are combined.

Recommended file: `location_source_mapping.csv`

Required columns:

```text
source,source_entity_id,source_entity_name,canonical_location_id
```

Example rows are provided in `location_source_mapping_sample.csv`. Keep source
values explicit (`WPI`, `PORTWATCH`, `INTERNAL`, and so on), and review mappings
when a provider changes its identifiers. Mapping files are processed inputs, not
raw provider extracts.

PortWatch mappings are maintained separately:

- `wpi_portwatch_port_mapping.csv` is the persistent mapping table between
  PortWatch `portid` and the WPI `location_id`. It is generated by the mapping
  builder and then consumed by normalization by source ID; normalization does
  not rematch names.
- `wpi_portwatch_review_queue.csv` contains numbered mapping candidates and
  unresolved source ports requiring confirmation.
- `portwatch_port_mapping.csv` is the earlier generated mapping artifact and is
  retained for history; new normalization uses the persistent
  `wpi_portwatch_port_mapping.csv` table.
- `portwatch_checkpoint_mapping.csv` maps PortWatch chokepoint IDs to canonical
  checkpoint IDs such as `CHK_SUEZ_CANAL`. Checkpoint IDs are not WPI locations.
- `portwatch_disruption_port_mapping.csv` is an optional manual override table
  for affected-port names that cannot be resolved from the persistent source-ID
  mapping, UN/LOCODE, or country-plus-name matching. Its columns are
  `event_id,source_port_name,canonical_location_id,match_method,match_confidence`.

The port table records source fields, WPI candidate fields, match method,
similarity, mapping status, and review reason. Only `AUTO_MATCHED`, `CONFIRMED`,
and `MANUAL_CONFIRMED` rows are normalized into canonical monitoring data.

`port_master_mapping.csv` is the effective WPI-preferred mapping consumed by
PortWatch monitoring and disruption processing. It maps every valid PortWatch
source ID either to a WPI `location_id` (`MATCHED_WPI`/`MANUAL_MATCH`) or to a
source-native `PW_PORT_<portid>` record (`SOURCE_NATIVE`).
