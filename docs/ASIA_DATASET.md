# Asia operational dataset

## Purpose

The active local runtime is a reproducible semi-synthetic Asia logistics
network. It is generated by `backend/app/asia_dataset.py` and loaded through the
existing SQLite repository into the canonical `RuntimeDataset` boundary.

The generator does not create a second file-based runtime model and does not
change routing, disruption policy, NetworkX scenario isolation, or assistant
grounding.

## Provenance model

| Dataset element | Provenance | Runtime treatment |
|---|---|---|
| Ports | Real geometry-bearing WPI-preferred canonical records from `data/processed/ports/port_master.parquet` | Existing canonical IDs, coordinates, WPI source, and UN/LOCODE where available; no synthetic duplicate |
| Factories | Synthetic enterprise entities near selected commercial port regions | Canonical `Location` with `location_type=FACTORY`, `source=SYNTHETIC` |
| Warehouses/DCs | Synthetic enterprise entities near selected commercial port regions | Canonical `Location` with `location_type=WAREHOUSE`, `source=SYNTHETIC` |
| Customers | Synthetic enterprise destinations near warehouse regions | Canonical `Location` with `location_type=CUSTOMER`, `source=SYNTHETIC` |
| Routes | Derived synthetic logistics connections grounded in endpoint coordinates | Canonical `Route` with geodesic distance, mode-based duration, estimated cost/capacity/risk, and `source=DERIVED_ASIA_SYNTHETIC` |
| Shipments | Controlled synthetic/semi-synthetic enterprise operations | Canonical `Shipment` with cargo, priority, deadline, ETA, status, and `source=SYNTHETIC` |
| Shipment route legs | Derived from deterministic candidate paths and simulated progress | Ordered canonical `ShipmentRouteLeg` records with `COMPLETED`, `CURRENT`, or `PLANNED` state |

## Generation assumptions

- The port subset is curated from existing canonical IDs; unresolved or
  geometry-missing PortWatch source-native rows are not forced into the network.
- Factory/warehouse/customer coordinates are small deterministic offsets from
  nearby real ports or warehouses and represent enterprise locations, not
  claimed public facilities.
- Routes are sparse directed logistics connections, not verified commercial
  services. Sea and road durations, costs, capacities, loads, and risk values
  are controlled research estimates.
- Shipment attributes and progress are synthetic. They are generated only after
  a feasible path exists in the derived NetworkX graph; route legs are never
  independently invented.
- A fixed `Random` seed controls topology attributes, shipment pair ordering,
  loads, priorities, and progress. `AsiaGenerationConfig` supports seed,
  shipment count, entity counts, and `region="Asia"`.

## Runtime boundary and legacy data

`repository.seed_master_data()` generates the dataset once and stores its
canonical entities in SQLite. `load_runtime_dataset()` exposes only the active
Asia records (`LOC_WPI_*`, `ASIA_*`) to routing and API services. The old
13-location compatibility fixture in `backend/app/data.py` remains for focused
legacy unit tests; it is not part of the active Asia runtime snapshot.

On an existing local database, the generated population is added without
deleting prior simulation history. Legacy master rows remain outside the active
runtime query until a later migration issue removes them after history and
foreign-key migration evidence is available.
